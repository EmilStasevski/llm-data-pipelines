# ADR 0009: pandas 3 contestants (a05/a06) and the GPU dataframe contestants (a07/a12)

- Status: accepted (Phase 4, 2026-11-07).
- Context: PLAN §8 was written for pandas 2 ("a05 = NumPy dtypes", "a06 = pyarrow engine + dtype_backend"). The installed stable pandas is **3.1.1** (df env) / **3.0.6** (gpu_df env, pinned by cudf 26.10), whose default string dtype `str` is already pyarrow-backed. a07 must run "the same code as a05" under cudf.pandas and log its CPU fallbacks; a12 must use `GPUEngine(raise_on_fail=True)`.
- Decisions:
  - **a05 = pandas defaults** (C parser, `dtype=str` → default `str` dtype). An expert writes the defaults; true NumPy object strings would be an artificial handicap in pandas 3.
  - **a06 = `engine="pyarrow"`, `dtype=pd.ArrowDtype(pa.string())`, `dtype_backend="pyarrow"`.** `dtype=str` would silently override the backend (caught by recording `string_dtype` in the result: `str` vs `string[pyarrow]`). `na_filter` is not supported by the pyarrow engine and is omitted.
  - a05/a06 share one transform (`zj_df/track_a/pandas_impl.py`) that imports only pandas/numpy/pyarrow. Component matching uses one lookahead regex over the forms (longest first) + explode; a 73× `str.find` variant was measured as barely faster (1.17 s vs 1.45 s at M) and was not kept.
  - **a07 imports the unchanged a05 module** (from `contestants/python/df/src`) after `cudf.pandas.install()`. Fallbacks are counted by wrapping `_fast_slow_function_call` (returns `(result, ran_on_gpu)`) in the cudf.pandas, pandas-wrapper and numpy-wrapper modules: a few hundred Python calls per run instead of the trace-based `--profile` (`sys.settrace` on every line would distort time and energy). Result extra: `engine` (`gpu` | `gpu+cpu_fallback`), `gpu_calls`, `cpu_calls`, `fallback_ops`, `fallback_counts`. The report marks such runs "⚠CPU fallback" (rule 6).
  - **a12 runs a10's plan unchanged** on `GPUEngine(raise_on_fail=True)`. Result on 2026-11-07: fails with 7 unsupported operations (NFC `normalize`, `extract_many`, `list.join`, the `(?i)` duration regex, regex `replace`, `replace_strict` without explicit default, strptime cache). NFC normalisation has no GPU equivalent, so a spec-conformant all-GPU plan is not possible; a12 stays at scale S so the loud failure is recorded every session (rules 4/6). A hand-split GPU/CPU hybrid would be an extra (`a12b`), open.
- Consequences: a05/a06/a07 differences are attributable to parser/dtype backend and to GPU acceleration of the same code. a07's numbers always come with its fallback profile.
